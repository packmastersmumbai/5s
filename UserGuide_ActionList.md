# PackMasters 5S — Action List User Guide

**Version:** v5.3.2 | **Date:** Feb 2026

---

## 1. What is the Action List?

The **Action List** (labelled "DO NOW — Action List" in the app) is a real-time dashboard that shows all outstanding corrective actions that need to be resolved across your 5S zones. It is a read-only view that aggregates actions from multiple sources — NC/CAPA records, Red Tag disposals, and open tasks — and ranks them by urgency so that supervisors and team leaders know exactly what to address first.

The list is generated automatically from QuickAudit low scores and other non-conformance workflows; no manual entry is required to populate it.

---

## 2. Who Should Use It?

| Role | Purpose |
|---|---|
| Zone Supervisor / Team Leader | Daily review of overdue and upcoming actions; delegation follow-up |
| 5S Coordinator | Cross-zone monitoring; escalation of CRITICAL items |
| Production Manager | High-level visibility of outstanding actions across all zones |
| Shopfloor Team Member | Confirming which task they are personally assigned to |

This page is intentionally read-only. Actions cannot be created, edited, or closed from this view.

---

## 3. How to Access

**Full URL pattern:**

```
https://script.google.com/macros/s/<DEPLOYMENT_ID>/exec?v2=1&action=actionlist&zone=<ZONE_ID>
```

**Example (Zone Z-01):**

```
https://script.google.com/macros/s/AKfycbw6GfjKqYmhprkF7tUJVofcAgGrK1ujjIhgtk7ETO2CG7BdtyxQkFlkR_Yym0uvCEJ8/exec?v2=1&action=actionlist&zone=Z-01
```

**From the app navigation:**

1. Open any PackMasters 5S page for your zone.
2. Tap the **Actions** icon in the bottom navigation bar (the lightning bolt icon, third from left).
3. The Action List for the current zone loads automatically.

**URL parameters:**

| Parameter | Required | Description |
|---|---|---|
| `v2=1` | Yes | Selects the v2 rendering engine |
| `action=actionlist` | Yes | Loads the Action List view |
| `zone=<ZONE_ID>` | Optional | Pre-filters results to a specific zone (e.g. `Z-01`). Omit to see all zones. |

> **Note:** The page loads data from Google Sheets via Apps Script. Allow 5–10 seconds after navigation for data to appear. A "Loading actions…" message is shown while data is being fetched.

## 4. Page Layout Overview

The Action List is divided into four horizontal sections, from top to bottom:

```
┌─────────────────────────────────────────────────┐
│  HEADER  — Title + Generated timestamp           │
├──────────┬──────────┬──────────┬────────────────┤
│ CRITICAL │   HIGH   │  MEDIUM  │     TOTAL      │  ← Summary Bar
├──────────┴──────────┴──────────┴────────────────┤
│  [All]  [Zone Name A]  [Zone Name B]  …          │  ← Filter Bar
├─────────────────────────────────────────────────┤
│  ▌ Action Card 1 (CRITICAL)                      │
│  ▌ Action Card 2 (HIGH)                          │
│  ▌ Action Card 3 (HIGH)                          │
│    …                                             │  ← Action Cards list
└─────────────────────────────────────────────────┘
│  Home  │  Board  │  Actions  │  Handover  │ More │  ← Bottom Nav
```

### 4.1 Header

- **Title:** "DO NOW — Action List" with a red vertical accent bar on the left.
- **Generated timestamp:** Displayed as a pill badge in the top-right corner (e.g. `24-Feb-2026 15:03`). This shows when the data snapshot was last generated by the server.

### 4.2 Summary Bar

A four-column grid immediately below the header showing counts for the current view:

| Column | Color | Meaning |
|---|---|---|
| CRITICAL | Red | Actions at the highest urgency level |
| HIGH | Amber/Orange | Actions at high urgency |
| MEDIUM | Dark amber | Actions at medium urgency |
| TOTAL | Grey | Sum of all visible actions |

The counts update automatically when a zone filter is applied.

### 4.3 Filter Bar

A row of pill-shaped buttons that filter the action card list by zone. See Section 6 for full details.

### 4.4 Action Cards List

The main scrollable area. Each action is rendered as a card with a colored left border. Cards are ordered by the server (typically most-urgent first). See Section 7 for a breakdown of each card's fields.

## 5. Understanding Urgency Levels

Each action is assigned one of three urgency levels. The level controls the card's left-border color and the badge label in the top-right of the card.

| Urgency | Left border color | Badge style | Meaning |
|---|---|---|---|
| **CRITICAL** | Red (`#C92A2A`) | Red text on pale red background | Overdue or high-risk; requires immediate action today |
| **HIGH** | Amber/Orange (`#E67700`) | Amber text on pale amber background | Due very soon or carrying significant cost/risk |
| **MEDIUM** | Gold (`#F59E0B`) | Dark amber text on pale yellow background | Upcoming action; address within the standard review cycle |

**How urgency is set:** Urgency is calculated automatically by the server based on due date proximity, source type (NC/CAPA, Red Tag, Task), and the score that triggered the action. Users cannot manually override urgency from this screen.

**Detail line color:** The detail line beneath every card title is always rendered in red regardless of urgency level. This is intentional — it draws the eye to the specific deficiency or status message.

## 6. Using the Zone Filters

The filter bar appears below the summary bar and contains one button per zone that has at least one action, plus an "All" button.

### Behavior

- **All** (default, shown with dark navy background when active): shows every action across all zones.
- **Zone button** (e.g. "Production Floor A"): narrows the card list to only actions belonging to that zone. The zone button becomes the active (dark navy) button; "All" returns to its unselected outline style.
- Clicking a zone filter **does not reload the page** — filtering is instant, client-side.
- The **Summary Bar counts do not change** when a zone filter is applied; they always reflect the totals for the full dataset loaded for the session.

### Filter buttons are generated dynamically

The filter buttons are built from the actual zones present in the data returned for the current session. If only one zone has actions, only one zone button appears alongside "All". If no actions exist, the filter bar will be empty.

### Pre-filtering via URL

If you add `&zone=Z-01` to the URL, the server returns only actions for zone Z-01. In this case, the filter bar will show only the zones present within that zone's data (which may still be more than one if the zone label in the data differs from the URL parameter).

## 7. Reading an Action Card

Each card contains the following fields:

```
┌──────────────────────────────────────────────┬──────────┐
│  Title                                        │  URGENCY │
│  Detail line (status / overdue message)       │  badge   │
│                                               │          │
│  Zone   Assigned   Due Date   Type + ID       │          │
└──────────────────────────────────────────────┴──────────┘
```

| Field | Position | Description | Example |
|---|---|---|---|
| **Title** | Top left, bold navy | Short action description | `Fix S1-C1 — Unnecessary items removed` |
| **Urgency badge** | Top right | CRITICAL / HIGH / MEDIUM label | `CRITICAL` |
| **Detail** | Below title, red text | Status message: overdue notice, pending days, cost info | `OVERDUE by 6 days` / `Pending 20 days, ₹15,000` |
| **Zone** | Meta row, first item | The zone or area where the action applies | `Production Floor A` |
| **Assigned** | Meta row, second item | Person or email address responsible | `Mr. Anuj Pathak` / `anuj.pathak@packmasters.in` |
| **Due Date** | Meta row, third item | Target completion date | `18-Feb-2026` |
| **Type + ID** | Meta row, fourth item | Source record type and unique reference number | `NC/CAPA NC-20260204-001` / `TASK TK-20260209-001` / `RED_TAG RT-20260204-001` |

**Left border color** mirrors the urgency level: red for CRITICAL, amber for HIGH, gold for MEDIUM.

**Assigned field format:** The assigned field may contain either a display name (e.g. `Mr. Anuj Pathak`) or an email address (e.g. `anuj.pathak@packmasters.in`) depending on how the originating record was created.

**If no actions exist:** The card area is replaced by a green "All clear — no outstanding actions" message, indicating the zone is fully compliant.

## 8. How Actions Are Generated

Actions are created automatically — they are never entered manually into the Action List.

### Sources

| Source type | ID prefix | Trigger condition |
|---|---|---|
| NC/CAPA | `NC-` | A QuickAudit criterion scores 0 or 1 (below threshold), generating a non-conformance record |
| Task | `TK-` | A follow-up task is created from a QuickAudit low-score item or an audit finding |
| Red Tag | `RT-` | An item is tagged during a Sort (Seiri) review and is pending disposal decision |

### Generation flow

1. An auditor or team leader completes a **QuickAudit** for a zone and scores one or more criteria below the acceptable threshold.
2. The system automatically raises a corrective action record (NC/CAPA, Task, or Red Tag) with a due date, assigned person, and urgency level.
3. The `getAutoActionList()` server function aggregates all open records from the Google Sheet backend and returns them sorted by urgency.
4. The Action List page calls this function on load and renders the results.

Actions are removed from the list automatically once they are closed or marked resolved in the source system (NC/CAPA, Task tracker, or Red Tag workflow). The Action List itself has no "mark complete" functionality.

## 9. Important Notes

- **Read-only page.** No data can be entered or changed from the Action List. To update an action, go to the source record (NC/CAPA form, Task detail, or Red Tag disposal screen).
- **Data freshness.** The generated timestamp in the header shows when the server snapshot was built. Refresh the page to retrieve the latest data.
- **Zone URL parameter vs. zone filter.** The URL `zone=` parameter controls which data is loaded from the server. The filter bar buttons then provide client-side sub-filtering within that loaded dataset. Changing a filter button does not issue a new server request.
- **Summary bar does not reflect filter state.** The CRITICAL / HIGH / MEDIUM / TOTAL counts in the summary bar always reflect the full dataset loaded for the session, not the currently filtered subset. This is by design — it gives an at-a-glance total picture even while a zone filter is active.
- **Detail line is always red.** The styling of the detail line (`color: var(--score-red)`) is fixed in the source. This is a deliberate design choice for visual urgency, not a bug, and applies equally to all urgency levels including MEDIUM.
- **Assigned field inconsistency (minor).** The assigned field may contain a full display name on some cards and an email address on others, depending on the originating record. This reflects how the record was authored and is not a display error.
- **Bottom navigation bar.** The "Actions" tab in the bottom nav (lightning bolt icon) is highlighted when the Action List is the active view. The other tabs (Home, Board, Handover, More) navigate to other parts of the PackMasters 5S app for the current zone.
- **Mobile use.** The page is fully responsive. On smaller screens the summary bar columns stack and the card list fills the full viewport width.

## 10. Troubleshooting

| Symptom | Likely cause | Resolution |
|---|---|---|
| Page shows "Loading actions…" indefinitely | Network issue or Apps Script quota exceeded | Wait 30 seconds and refresh. If the problem persists, check Google Apps Script service status. |
| Page shows a red error message instead of cards | Server-side error in `getAutoActionList()` | Note the error text and report to the 5S system administrator. |
| "All clear — no outstanding actions" shown but you expect actions | Actions may have been closed in the source system, or the `zone=` URL parameter is filtering to a zone with no open actions | Verify the zone ID in the URL and check the source records directly. |
| Filter buttons are missing | The data returned contained no zone field values (empty zone column in source sheet) | Report to the 5S system administrator to review data integrity. |
| Summary bar shows higher totals than visible cards | A zone filter is active — the summary always shows totals for the full dataset | Click "All" in the filter bar to see all actions. |
| An action does not appear even though it was raised | The action record may not yet be saved, or it may be marked closed | Wait a few minutes and refresh. If it still does not appear, check the source record status. |
| Urgency badge color looks wrong (e.g. MEDIUM card has amber border) | No known bug — urgency assignment is server-side | If urgency appears systematically incorrect, report to the 5S system administrator with the record ID from the meta row. |
| Page loads but no data, no error, and no "All clear" message | Rare edge case: data object returned null | Refresh the page. If it recurs, report to the administrator. |
